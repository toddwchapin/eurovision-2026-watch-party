## Expanded regression coverage

The canonical command remains `npm test`: it executes all three Playwright projects, not just Chromium. Install browsers with `npx playwright install --with-deps chromium firefox webkit`. CI retains Node 24.12.0/Java 21, uses a 40-minute job timeout and 60-second per-browser-test timeout, and installs all engines. Playwright is pinned to 1.64.0; axe is development-only.

New deterministic SDK/emulator browser gates cover:
- Full axe default-rule scans (no disabled violations) of named host and invited guest onboarding, rating, populated party results with expanded guest breakdown, trivia content and its named explanation dialog. Keyboard explanation activation, focus containment, Escape/Close and focus return are asserted.
- Two authenticated guests seeded through their own permitted SDK writes: rendered score averages, descending order, running-order ties, joint winners, individual totals, and trivia averages/comment lengths/name-ordered ties. Local unsubmitted drafts cannot enter aggregates.
- A genuinely offline submitted vote plus a different-act partial draft survive abrupt document loss, preserve the durable queue, and recover to a server-read acknowledged vote. Chromium uses real CDP `Page.crash`; Firefox/WebKit dispose the document without unload handlers because they expose no renderer-crash API. This is not whole-browser/OS power-loss certification.
- Reload while both RTDB HTTP and WebSocket transport are blocked preserves the exact operation ID/payload and draft, reports the real bootstrap timeout, then shares on restored connectivity. Static HTML and Auth remain available in this targeted RTDB outage; uncached fully offline page loading is not promised.
- Reset and leave each run with the SDK merge packet withheld before commit, and separately with the actual emulator acknowledgement withheld after commit. The initiating SDK promise stays unresolved and its optimistic snapshot remains durable. After page loss, a fresh SDK connection reads server state: noncommitted destruction preserves votes/drafts, committed destruction clears drafts/votes, and leave/rejoin retains tombstones without resurrection. These are real transport/emulator faults, not fabricated SDK return values.

Minimal production-source fixes discovered by axe: native main landmarks on rating/results/trivia; onboarding heading level 2 with unchanged heading CSS and dialog label lookup; and a named/described trivia explanation dialog with keyboard-reachable cards, themed Close, inert background, focus containment/return. No score arithmetic, sync/rules behavior or palette was changed. A real cold-reload race found in Firefox could open the rating form before Auth supplied its UID, showing an empty draft under the wrong storage key; Start Rating now waits for authenticated local key initialization, explicitly resets its initial disabled state and opts out of Firefox’s persisted dynamic button-state restoration (`autocomplete="off"), with a delayed real Auth-emulator request proving that a saved draft restores. An existing offline-tab test race was fixed by waiting for essential subscriptions (`EurovisionSession.ready`), rather than interpreting an early Shared status as subscription readiness.

### Platform limitation and Linux fallback

Native macOS 27 Firefox cannot launch: its generic “Could not find profile folder” failure occurs before any app/test runs. Multiple Playwright browser revisions were probed; an older revision also showed the upstream `sandbox_extension_issue_file_to_process` denial. This matches [upstream issue #42082](https://github.com/microsoft/playwright/issues/42082). No Firefox tests are skipped and native `npm test` therefore correctly exits nonzero on this host. Chromium and WebKit execute natively.

Use `bash scripts/test-linux.sh` with local Docker to run the identical clean install, full suite and regressions in Playwright's Ubuntu container, with exact Node 24.12.0 and Java 21. The checkout is mounted read-only, copied inside a disposable container (including baseline git objects); no ports/production credentials are mounted. It supports arm64/x64 and copies reports/traces outside git to `~/.hermes/cache/scratch/party-linux-artifacts` (override `PARTY_TEST_ARTIFACTS`). The first container setup attempt lacked `xz-utils` and failed before tests; the script explicitly installs it.

## Review-blocker verification

- Deterministic tests execute the complete shipped session helper: denied reset/leave preserve pending votes, cached votes and drafts through optimistic events/rollback; acknowledged destruction cancels them; other-tab edits survive failure; other-tab acknowledged or successfully reset work is not revived. Essential subscription failure survives a successful in-flight write and empty flush, disables save/readiness, and clears only on the affected listener's recovery.
- Two emulator tests execute the same shipped helper through a thin real modular-SDK adapter. An injected forbidden payload field forces an actual server `PERMISSION_DENIED`; assertions require the SDK's optimistic epoch increment and rollback, intact pending/drafts/local votes, and unchanged remote membership/name/epochs. An independent same-identity SDK connection is verified not to receive the rejected operation's optimistic epoch. The deterministic adapter covers exact interleavings; it does not substitute for these real SDK/emulator denials.
- Emulator tests deny deletion of each stage epoch, the epochs subtree, the whole user, replacement omitting tombstones and party-root user deletion. They verify an overlapping same-identity new-epoch save cannot land during atomic leave, failed leave changes nothing and permits subsequent member saves, rejoin retains tombstones and rejects stale epoch-zero writes, and vote-plus-epoch updates use the post-update epoch.
- The browser denial gate now expects Save disabled after membership/subscription revocation and additionally performs a direct real SDK write to assert `PERMISSION_DENIED`; it never counts disabled UI alone as proof of enforcement.
- Regression probing now executes the entire current session helper (including its closure dependencies), not an extracted reset function with obsolete VM globals. Baseline and deliberate sabotage still fail for their intended contract violations.
- Destructive SDK updates intentionally remain pending if connectivity is lost after dispatch: only definitive acknowledgement/rejection resolves the operation. Expanded crash/restart fault-injection is described below; no physical-device certification is claimed.
